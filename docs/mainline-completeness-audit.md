## Current executable path

    frontend/src/main.tsx
      → AppShell.tsx
      → / renders ChildPortalPage
      → Home fetches /api/children/{child_id}/learning-daily-queue
      → Home “start today” callback passes LEARN; due-review CTA passes REVIEW
      → AppShell stores launch lesson + mode and navigates to /learning-session
      → AppShell renders LessonPlayerPage with the selected initialMode
      → backend POST /api/children/{child_id}/learning-sessions builds tasks
      → task answer/evidence APIs write attempts, gates, and SRS
      → POST .../complete atomically checks required tasks, assesses mastery, awards 5 points, and settles session + telemetry
      → onBack returns to /

The backend also exposes /api/children/{child_id}/learning-sessions/report and a parent-authorized placement profile API. The production Parent Dashboard does not consume the learning-session report, and the production frontend does not call the placement profile API. Issue #51 tracks the Parent Dashboard integration as `OWNER_DECISION_REQUIRED`: the report requires a signed parent/admin session and adding its data to the parent surface would touch the UI lane the owner asked to keep manual. This owner gate does not block backend mainline work.

When the current lesson is complete and the Daily Queue has due reviews, the Home CTA carries REVIEW through AppShell to the canonical `/learning-session` route. The ordinary lesson CTA explicitly carries LEARN. AppShell resets launch intent when leaving the session route through Home navigation or browser history, so REVIEW cannot persist into a later normal launch. PR #46 reconciles exact due recognition rows across the three existing executable packages, selects exact child/session/lesson/item task rows, and builds each step from its own package. PR #60 extends this exact reconciliation to supported writing and word SRS items, synchronizes retry due dates, and preserves REVIEW's parent LEARN lifecycle. PR #62 adds the exact Fast Track listening question as a scored REVIEW task; its SRS update commits atomically with task attempts/state and telemetry, without curriculum mastery evidence. Listening answers use literal package choice IDs and cannot settle or award mastery for the parent LEARN session. No visual direction or layout changed.

PR #40 aligned backend planner tasks with executable player steps for the three supported lesson IDs. Its real API regressions cover planner output, exact task evidence, and settlement for full and supported partial recognition plans. It did not change adaptive/teaching policy, mastery thresholds, SRS policy, or the UI.
